## Code Generation Rules

### 1. Latency First
Every code change must consider latency impact:
```python
# ✅ GOOD: Minimal, fast
async def generate_response(self, message: str) -> str:
    response = await self.model.generate_content_async(message)
    return response.text

# ❌ BAD: Extra processing adds latency
async def generate_response(self, message: str) -> str:
    # Don't add: sentiment analysis, content moderation, logging overhead
    preprocessed = await self.preprocess(message)  # Avoid extra steps
    response = await self.model.generate_content_async(preprocessed)
    postprocessed = await self.postprocess(response.text)
    return postprocessed
```

### 2. Minimal Imports
```python
# ✅ GOOD: Only what's needed
from fastapi import APIRouter, Request
from ai_receptionist.services.ai import GeminiService

# ❌ BAD: Importing unused libraries
from fastapi import APIRouter, Request, BackgroundTasks, Depends
from typing import Optional, List, Dict, Any
import pandas as pd  # Not used
from ai_receptionist.db import get_session  # No database!
```

### 3. No Premature Optimization
```python
# ✅ GOOD: Simple, readable
def calculate_cost(input_tokens: int, output_tokens: int) -> float:
    input_cost = (input_tokens / 1_000_000) * 0.075
    output_cost = (output_tokens / 1_000_000) * 0.30
    return input_cost + output_cost

# ❌ BAD: Over-engineered
class CostCalculator:
    def __init__(self, pricing_strategy: PricingStrategy):
        self.strategy = pricing_strategy
        self.cache = {}
    
    async def calculate_with_cache(self, tokens: TokenCount) -> Money:
        # Unnecessary abstraction for a simple calculation
        ...
```

### 4. Async by Default
```python
# ✅ GOOD: Async for I/O operations
async def log_latency(metrics: dict) -> None:
    async with aiofiles.open('data/latency_logs.jsonl', 'a') as f:
        await f.write(json.dumps(metrics) + '\n')

# ❌ BAD: Blocking I/O
def log_latency(metrics: dict) -> None:
    with open('data/latency_logs.jsonl', 'a') as f:  # Blocks event loop
        f.write(json.dumps(metrics) + '\n')
```

### 5. Configuration via Environment
```python
# ✅ GOOD: Pydantic Settings
from pydantic_settings import BaseSettings

class Settings(BaseSettings):
    gemini_api_key: str
    gemini_model: str = "gemini-2.0-flash-exp"
    twilio_auth_token: str
    
    class Config:
        env_file = ".env"

# ❌ BAD: Hardcoded or complex config files
GEMINI_API_KEY = "hardcoded-key-123"  # Security risk
# or
import yaml
config = yaml.safe_load(open('config.yaml'))  # Unnecessary complexity
```

## Common Anti-Patterns to Avoid

### ❌ Adding "Just in Case" Code

```python
# ❌ DON'T: Add features we might need later
class GeminiService:
    def __init__(self):
        self.cache = {}  # "Might need caching later"
        self.rate_limiter = RateLimiter()  # "Might hit limits"
        self.fallback_model = OpenAI()  # "Might need backup"

# ✅ DO: Add only what's needed NOW
class GeminiService:
    def __init__(self, api_key: str, model: str):
        self.client = genai.GenerativeModel(model)
```

### ❌ Over-Abstracting

```python
# ❌ DON'T: Create layers of abstraction
class AIServiceFactory:
    def create_service(self, provider: str) -> AIService:
        ...

class AIServiceProvider(ABC):
    @abstractmethod
    async def generate(self) -> str:
        ...

# ✅ DO: Direct, simple implementation
class GeminiService:
    async def generate_response(self, message: str) -> str:
        ...
```

### ❌ Adding Monitoring Infrastructure

```python
# ❌ DON'T: Add Prometheus/StatsD/DataDog
from prometheus_client import Counter, Histogram
requests_total = Counter('requests_total', 'Total requests')

# ✅ DO: Use JSONL logging + experiment_matrix.py
await log_latency({
    'timestamp': datetime.now().isoformat(),
    'ai_latency_ms': ai_latency,
    'total_latency_ms': total_latency,
})
```

### ❌ Testing Infrastructure

```python
# ❌ DON'T: Add pytest, fixtures, mocks
@pytest.fixture
async def db_session():
    ...

@pytest.mark.asyncio
async def test_webhook_with_mocks(mocker):
    ...

# ✅ DO: Use experiment_matrix.py for real API tests
# Manual testing: curl -X POST http://localhost:8000/twilio/webhook
```

## When User Asks For...

### "Add analytics"
→ Use experiment_matrix.py to measure latency/cost metrics
→ Analyze data/latency_logs.jsonl with jq or Python
→ **DON'T** add databases, dashboards, or analytics services

### "Add monitoring"
→ Use self_improver.py for continuous regression detection
→ Export data/latency_logs.jsonl to external tools if needed
→ **DON'T** add Prometheus, Grafana, or DataDog agents

### "Add testing"
→ Use experiment_matrix.py for automated latency experiments
→ Manual testing with Twilio webhook calls
→ **DON'T** add pytest, unit tests, or test infrastructure

### "Add logging"
→ Use latency_logger.py (already implemented)
→ JSONL format to data/latency_logs.jsonl
→ **DON'T** add structured logging libraries (loguru, structlog)

### "Add caching"
→ First measure: Does latency actually warrant caching?
→ Use experiment_matrix.py to compare cached vs non-cached
→ **DON'T** add Redis, Memcached, or in-memory stores prematurely

### "Add authentication"
→ Twilio already validates requests with auth tokens
→ Check TWILIO_AUTH_TOKEN in webhook validation
→ **DON'T** add JWT, OAuth, or session management

### "Improve performance"
→ Run experiment_matrix.py to establish baseline
→ Profile with self_improver.py to detect regressions
→ Focus on: async I/O, minimal processing, prompt optimization
→ **DON'T** add queues, workers, or distributed systems

### "Add a feature"
→ Ask: Does this increase latency?
→ Ask: Does this require new dependencies?
→ Ask: Is there a simpler way?
→ **Measure impact** with experiment_matrix.py
